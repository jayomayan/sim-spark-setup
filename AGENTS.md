- Router work never runs in the app server: SNMP, UR35 config, ping and Site Connectivity Check captures all use `agent_jobs` and the on-network helper, so one install covers everything.
- Share homepage session state via the root auth listener and SignedInContext.
- Encrypted helper settings live in admin-only `public.helper_settings`; stable login IDs preserve only their own secret. Router jobs use the helper SSH module with ordered logins, authentication-only retries and pinned host keys. Probe CLI readback before changes; preserve unrelated router settings, save/read back without reboots or write replay. Machines pull settings/releases; legacy columns serve old helpers. `src/lib/helper-release.ts` is the tested version source.
- Supported router jobs are defined in `src/lib/job-types.ts` and validated before queueing and dispatching so retired jobs cannot execute.
- Firewall progress uses bounded stage/count events, never output or secrets.
- The helper atomically rewrites UR35_Credentials.txt (mode 0600) with ordered login pairs on every settings refresh; the config revision advances only after the write succeeds so failures retry without exposing plaintext.
- Site Connectivity Check (formerly Private Browser; /private-browser stays as a redirect) runs `site_capture` and `site_ping` helper jobs; the page validates canonical RFC1918 IPs before queueing and parses job results with the zod schemas in `src/lib/site-connectivity.ts`. The helper's Playwright capture allows ports 80/443/8443/8080, with 8080 tried over HTTP then HTTPS because devices use either, and request interception pins the browser to the exact target IP; Linux ping uses fixed four-probe arguments without a shell. The retired standalone service remains under `public/site-connectivity-service` as a reference only.
- Access is role-gated: data RLS requires a `user_roles` row (`is_member`); the first signup becomes admin and admins grant others through Admin Settings; /users remains a guarded compatibility URL.
- External invitations use normalized unique usernames mapped to deterministic non-deliverable auth addresses; contact email and phone stay in profiles. Account-security flags are service-write-only and block has_role/is_member plus protected navigation until a current-password-verified server action sets a strong new password; no password is emailed or persisted by app code.
- Invitation auditing reserves a durable record before account creation and records outcomes with explicit credential-free fields; history is admin-read-only and survives account deletion so failed attempts and past invitations remain traceable.
- Invitation password generation uses browser cryptographic randomness; credentials are copied only on explicit admin action and retained after submission only in transient component state, never browser storage or audit records.
- Admin Settings routes gate on the parent role context, and every settings server function independently validates the caller's admin role through RLS before any privileged work; managed database credentials are never returned.
- Alternate-database connection profiles live in `public.database_connections` (admin-only RLS); passwords are AES-256-GCM encrypted in `src/lib/db-connection.server.ts` with the `DB_SECRET_KEY` secret and are never returned to clients. Connection tests use a real Postgres handshake (`postgres` package); the app's own data always stays on the configured primary connection.
- Standalone builds use standard Vite/TanStack/React/Tailwind/Nitro plugins with a Node target and isolated environment directory; their auth-storage alias uses origin-local browser persistence instead of the preview broker. Hosted `vite.config.ts` and generated integrations remain unchanged. The backend must supply compatible auth/data APIs, not just PostgreSQL. `deploy/migrate.mjs` applies the checked-in journal transactionally, records private checksums and refuses untracked restored schemas.
- The native installer uses existing local PostgreSQL without creating clusters or altering database-server settings; existing databases/required roles cause refusal rather than replacement. It supports existing Nginx hosts with private runtimes and saved connection ports; unrelated resources and partial state remain intact. Reuse only explicitly approved dormant, locked, dedicated service accounts, revalidated before use. Upgrades read saved connection metadata with legacy defaults.
- Native upgrades stage app builds before downtime, preserve private settings, back up the database before migrations and stop for manual recovery after uncertain migration commits; backend/runtime upgrades stay separate to avoid implicit incompatible cutovers.
- External PostgreSQL setup runs only through an independently admin-authorized server function, creates missing databases through the postgres maintenance database, and applies versioned transactional tables in an isolated field_ops schema with owner-only access; this preserves unrelated tables and never clones managed auth or performs an implicit cutover.
- Okta is backend-configured; tests use Authorization Code discovery, never token grants. Verified identities provision operator access via ensure_okta_access, preserving roles/password gates; native hooks restrict signup and Auth owns linking.
- Console Connect reads and writes only the Site ID Lookup configuration; SIM operations resolve that same API destination and use the shared password-grant token/request helpers, ignoring retired SIM rows to prevent configuration drift. Passwords reuse encrypted credential storage and are never returned. Member-authorized operations load configuration after is_member validation. Existing Site ID environment credentials remain the fallback; edited destinations are restricted to official provider HTTPS domains. All Console Connect requests use consoleFetch with redirect manual and explicit 3xx rejection: Workers do not support redirect error, and credentials must never be forwarded.
